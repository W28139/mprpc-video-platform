# log3: 将 wevix_muduo 接入 mprpc 框架

## 日期
2024-07-23

## 变更目的
将 mprpc 框架的网络层从**原版 muduo (chenshuo/muduo)** 替换为自研的 **wevix_muduo** 网络库。

```cpp
{

    }
}
```

| 文件 | 改动行 | 说明 |

#### 3.1 Run() 函数
```cpp
// Before: 手动创建 EventLoop + TcpServer + 启动循环
muduo::net::InetAddress address(ip, port);
muduo::net::TcpServer server(&m_eventLoop, address, "RpcProvider");

// ...

// After: TcpServer 自管理 EventLoop

// server.start() 内部启动 mainLoop + subLoops

```

#### 3.2 OnConnection / OnClose 拆分
```cpp
// Before: muduo 的 OnConnection 在连接/断开时均触发，需判断状态
void OnConnection(const muduo::net::TcpConnectionPtr& conn) {
    if (!conn->connected()) {
        conn->shutdown();  // 断开时关闭
    }
}

// After: 拆分为两个独立回调
void OnConnection(const ConnectionPtr& conn) {
    // 仅在新连接建立时触发
    std::cout << "New connection from " << conn->ip() << ":" << conn->port() << std::endl;
}
void OnClose(const ConnectionPtr& conn) {
    // 在连接断开时触发
    std::cout << "Connection closed" << std::endl;
}
```

#### 3.3 OnMessage 简化
```cpp
// Before: 需手动从 Buffer 提取数据
void OnMessage(conn, Buffer* buf, Timestamp time) {
    std::string recv_buf = buf->retrieveAllAsString();  // 手动提取
    // ... 从 recv_buf 解析
}

// After: message 已经是完整字符串（wevix_muduo 在 Connection::handleRead 中已提取）
void OnMessage(conn, std::string& message) {
    // 直接从 message 解析，无需再调 retrieveAllAsString()
    // 后续协议解析逻辑完全相同
}
```

## OnMessage 开销分析

### 原版 muduo 的路径（1次内存拷贝）

```
epoll_wait → Channel::handleEvent() → Connection::handleRead()
    → inputBuffer_.readFd()           // 从内核读到 Buffer（readv 零拷贝）
    → onMessageCallback_(conn, buffer)  // 回调，buffer 指向 Buffer 对象
        → [用户] buf->retrieveAllAsString()  // ★ 第1次拷贝：Buffer → std::string
```

用户可以选择**不拷贝**（用 `peek()`），或按需部分消费（`retrieve(n)`）。

### wevix_muduo 的路径（优化前：4次内存拷贝 → 优化后：1次）

**优化前：**
```
epoll_wait → Channel::handleEvent() → Connection::handleRead()
    → inputBuffer_.readFd()                // 从内核读到 Buffer（readv 零拷贝）
    → std::string message = 
        inputBuffer_.retrieveAllAsString()  // ★ 拷贝#1: Buffer → string
    → connectionCallback_(conn, message)
        → TcpServer::handleMessage(conn, message)
            → std::string msg = message;   // ★ 拷贝#2: string → string (多余!)
            → submitInWorkPool(
                [this, conn, msg]()         // ★ 拷贝#3: lambda 按值捕获 (多余!)
                {
                    std::string tmp = msg;  // ★ 拷贝#4: string → string (多余!)
                    onMessageCallback_(conn, tmp);
                });
```

**优化后（已实施）：**
```
epoll_wait → Channel::handleEvent() → Connection::handleRead()
    → inputBuffer_.readFd()                // 从内核读到 Buffer（readv 零拷贝）
    → std::string message = 
        inputBuffer_.retrieveAllAsString()  // ★ 拷贝#1: Buffer → string
    → connectionCallback_(conn, message)
        → TcpServer::handleMessage(conn, message)
            → workThreadPool_ == nullptr
            → onMessageCallback_(conn, message)   // 直接透传引用，零额外拷贝
                → [用户] RpcProvider::OnMessage
```

### 结论

| 指标 | 原版 muduo | wevix_muduo (优化后) | 说明 |
|------|-----------|---------------------|------|
| 字符串拷贝次数 | **1** | **1** | ✅ 持平 |
| epoll 到用户回调的 CPU 开销 | 基准 | **持平** | 无额外 memcpy |
| 有 work pool 时 | N/A | 1 次 move + shared_ptr | 比拷贝高效 |

**"传入 string 而不是 Buffer"这个设计选择本身没有性能问题**——原版 muduo 的用户回调里也会调用 `retrieveAllAsString()` 创建相同的 string。问题只出在 `TcpServer::handleMessage()` 的多余拷贝层，现已修复。

**优化实施**（2024-07-23）：
```cpp
// src/TcpServer.cpp — 优化后的 handleMessage
void TcpServer::handleMessage(const ConnectionPtr& conn, std::string& message)
{
    if (!onMessageCallback_)
        return;

    if (workThreadPool_)
    {
        // 有 work pool：shared_ptr + move，1 次 move + refcount
        auto msg = std::make_shared<std::string>(std::move(message));
        workThreadPool_->addTask([this, conn, msg]() {
            onMessageCallback_(conn, *msg);
        });
    }
    else
    {
        // 无 work pool：直接透传引用，零额外拷贝
        onMessageCallback_(conn, message);
    }
}
```

## 总结

| 维度 | 评估 |
|------|------|
| 功能完整性 | ✅ TcpServer/Connection/Buffer/EventLoop 覆盖所有 muduo 使用场景 |
| API 兼容度 | 🔶 ~70%，核心概念一一对应，需要适配构造和回调签名 |
| 编译结果 | ✅ wevix_muduo + mprpc 均零错误通过 |
| OnMessage 性能 | ✅ 已优化至 1 次拷贝，与原版 muduo 持平 |
| 内存管理 | 🆙 优于 muduo — 内置内存池（Channel operator new 走 MemoryPool） |
| 外部依赖 | 🆙 消除 muduo 系统依赖 + 无 Boost 依赖 |
| 可控性 | 🆙 完全自主 — 可自由定制网络层行为 |
