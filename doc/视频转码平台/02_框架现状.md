# 02. 框架现状与剩余缺口

## P0 已全部完成

mprpc 基础框架经过 log 3 ~ log 10 共 8 轮迭代，P0 阶段正式完结。详见 `doc/my_log/10. mprpc基础框架P0最终收尾——初始框架完结.md`。

当前框架能力概览：

| 维度 | 状态 |
|------|------|
| 协议帧 | magic/version + 网络字节序 + 帧大小上限 + deadline_ms |
| 错误语义 | 15 种 `RpcErrorCode`，双向结构化错误回传 |
| 服务发现 | ZK 临时顺序节点 + `GetChildren` 多实例 + 本地轮询 |
| 客户端缓存 | ServiceCache → SharedZkClient → ConnectionPool 三层 |
| 连接复用 | endpoint 连接池，长连接复用，失败自动重试 + 重新发现 |
| 服务端并发 | IO 线程 + work pool 分离，业务不阻塞网络 |
| 框架初始化 | `Init()` 返回 bool，`Run()` 返回 bool |
| 防御性 | 服务端主动拒绝过期请求 |
| 契约 | 服务对象所有权、done 调用规范已文档化 |

## 剩余缺口（5 项）

这些不是现在要改的，按视频平台开发阶段按需补。详细分析见 log10 末尾。

| # | 缺口 | 触发阶段 | 工作量 |
|---|------|---------|--------|
| 1 | ZK session expired 自动重注册 | Worker 注册/心跳 | 中 |
| 2 | ZK GetData 128B 硬截断 | Worker metadata 注册 | ~10行 |
| 3 | RpcProvider 无优雅关闭 | Worker 进程管理 | ~40行 |
| 4 | RPC_OVERLOADED 错误码 + work queue 上限 | mock 高并发 | ~30行 |
| 5 | TCP keepalive + 连接池空闲回收 | 多机部署 | ~20行 |

## 核心原则

> 先开始视频平台业务。业务遇到真实需求时，再把对应 RPC 能力补成通用框架能力。

框架已足够支撑视频平台 MVP。不要再在框架上无限打磨。
