## 3. 对 C++ 方向的重新判断

最开始的判断逻辑是：

> Java 门槛低，人多，985/211 也会学，双非不好出头；  
> C++ 难度高，可以靠硬实力展示自己，因此更适合突围。

这个判断有一半是对的。

正确部分：

- 双非想突围，不能只做普通 CRUD 项目。
- C++ 的 muduo、mprpc、内存池等项目，确实比普通 Java 管理系统更能展示技术能力。
- 如果在双非里能力较强，C++ 底层项目可以拉开差距。

误判部分：

- C++ 不是空窗，而是窄门。
- C++ 岗位少，面试深，业务场景集中。
- 很强的 985/211 学生并不都去算法和大模型，也会去数据库、存储、基础架构、交易系统、云基础设施、自动驾驶系统软件等 C++ 强区。
- C++ 不是避开强者，而是进入另一个强者密度不低、岗位更少的赛道。

更准确的判断：

> Java 是大池子，大量普通人竞争，但岗位也多。  
> C++ 是小池子，普通人少一些，但水更深，岗位更少。  
> 双非走 C++ 可以突围，但前提是项目必须完整、可运行、可压测、可讲清楚。

最终结论：

> C++ 不是错误路线，而是就业容错率低的路线。  
> 当前不应该全盘转 Java，也不应该死磕纯 C++ 后端。  
> 更理智的方式是继续 C++ 主线，同时扩大岗位池。

## 5. 哪些方向吃学历

已经明确不作为主攻的方向：

- 分布式数据库核心。
- 存储引擎核心。
- 机器人算法、SLAM、规划控制。
- 自动驾驶算法。
- 操作系统内核、驱动。

这些方向吃学历、吃长期积累、吃实验室/论文/实习背景，不适合作为当前主投方向。

剩余方向学历压力如下：

## 6. 是否转 Qt

结论：

> Qt 合适，但不适合作为当前主线。  
> 它更适合作为 C++ 主线的保底扩展。

原因：

- 直接全转 Qt，会浪费已有的 muduo、mprpc、内存池、Linux 网络编程积累。
- Qt 的岗位常在工业软件、仪器设备、上位机、客户端工具、机器人控制台等方向。
- 这些岗位对学历的硬筛通常弱于大厂 C++ 基础架构。
- 但 Qt 上限一般不如 C++ 服务端、音视频平台、基础软件、嵌入式系统软件。

最划算的做法：

> 给视频转码平台加一个 Qt 管理端。

可以做的功能：

- 提交视频转码任务。
- 查看 Job 列表。
- 查看 Shard 进度。
- 查看 Worker 在线状态。
- 展示错误日志。
- 支持取消任务。

这样一个项目可以同时适配：

- C++ 服务端。
- 音视频平台。
- Qt / 上位机。
- 工业软件。
- 测试开发 / 工具开发。

## 7. 当前项目策略

### 不建议继续扩张的项目

不建议再开：

- `io_uring + C++20 协程 + 分布式存储引擎`。
- 独立分布式 KV。
- 继续堆消息队列、存储引擎、底层轮子。

原因：

- 没有业务支撑，容易被面试官追问 Raft、一致性、WAL、快照、选主、脑裂、Compaction、恢复语义。
- 如果只实现一部分，容易被判断为玩具项目。
- 与当前视频平台和 mprpc 的技术叙事重复，且风险更高。

### 推荐主项目

主项目应聚焦：

> 基于自研 muduo 与 mprpc 的分布式视频处理与资源调度平台。

它的价值在于：

- 有业务闭环。
- 可以自然使用 RPC、服务发现、Worker 调度、心跳、重试、幂等、压测。
- 比单纯 muduo/mprpc demo 更像真实工程。
- 可以通过 FFmpeg executor 打开音视频岗位。
- 可以通过 Qt 管理端打开工业软件/上位机岗位。

## 10. C++ 学习周期判断

如果从零开始，C++ 服务端到可投递通常需要：

| 阶段 | 时间 | 能力 |
|---|---:|---|
| C++语法/STL/面向对象 | 1-2个月 | 能写普通业务代码 |
| Linux/网络/多线程 | 2-3个月 | 能写 TCP server、线程池、epoll demo |
| 项目阶段 | 2-4个月 | muduo/mprpc/IM/业务平台 |
| 面试补齐 | 1-2个月 | 八股、项目表达、刷题、投递迭代 |

普通人从零到可投 C++ 服务端，大约 6-10 个月。

到有竞争力，通常需要 10-18 个月。

当前情况：

> 已经走过前半段，现在缺的是项目闭环、压测、实习投递，而不是重新学 C++。

## 14. CCPC 省金的价值

CCPC 河南省赛金牌有实际加分。

作用：

- 证明算法基础和训练强度。
- 对双非简历有帮助，能缓解“学校一般”的第一印象。
- 配合 C++工程项目，可以证明不是只会跟教程写项目。

限制：

- 不能替代实习。
- 不能替代工程项目闭环。
- 不能直接兑换 offer。

更准确的定位：

> 竞赛做筛选突破，项目做工程可信度，实习做就业定价。

## 15. 建议

如果刚开始选方向，且目标是普通本科最大就业概率：

> 更建议 Java 后端 + AI 应用 / Agent 工程化。

原因：

- Java 岗位池更大。
- 对双非容错率更高。
- 能覆盖政企软件、企业服务、制造业数字化、SaaS、AI应用平台。
- AI Agent 可以作为差异化加分项。

不建议学弟直接走：

- 纯 AI 算法。
- 只会调 API 的 AI Agent 项目。
- 一开始就深扎 C++ 纯后端。

适合学弟的项目：

- 企业知识库 / RAG 问答系统。
- 智能客服 / 工单 Agent。
- Java 后端业务系统 + AI 能力接入。

如果非常喜欢 Linux、操作系统、网络、嵌入式、机器人、音视频，并且愿意长期啃底层，才建议 C++。

## 17. 简历表达原则

不要写：

> 手写 muduo、手写 mprpc、手写内存池。

更推荐写：

> 基于 Reactor 模型实现 C++ 网络库，并在其上构建 RPC 框架，最终支撑分布式视频处理与资源调度平台。

项目描述应突出：

- 业务问题。
- 技术方案。
- 性能数据。
- 故障场景。
- 可恢复性。
- 可观测性。

示例表达：

> 基于自研 C++ 网络库和 RPC 框架实现分布式视频处理调度平台，支持视频任务提交、任务切片、Worker 注册与心跳、资源感知调度、失败重试、进度上报和结果聚合。系统通过 ZooKeeper 实现服务注册发现，通过长连接 RPC 完成调度器与 Worker 通信，并基于任务状态机保证 Worker 故障后的任务恢复。

## 18. 最终判断

当前路线不是错路线，而是难路线。

需要修正的不是“是否继续 C++”，而是：

- 不要继续把 C++ 当作避开竞争的路线。
- 不要死磕纯 C++ 后端。
- 不要继续堆底层轮子。
- 不要把项目停留在学习痕迹。

更合理的路线：

> C++ 服务端 / 分布式任务调度 / 音视频平台工程作为主线；  
> Qt / 工业软件 / 嵌入式 Linux / 测试开发作为保底扩展；  
> 用竞赛突破初筛，用项目证明工程能力，用实习提高毕业定价。

一句话结论：

> 你现在不该转向，也不该继续扩张。  
> 你该把 C++ 从“底层学习成果”收束成“一个完整业务系统 + 一个保底 Qt 管理端”。
