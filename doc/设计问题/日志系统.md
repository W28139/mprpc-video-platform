# 日志系统参考手册

> **源码位置**：`wevix_muduo/include/wevix_muduo/AsyncLogger.h` + `wevix_muduo/src/AsyncLogger.cpp`
>
> **一切入口**：`#include "wevix_muduo/AsyncLogger.h"`

---

## 一、架构总览

```
   业务线程 (N 个)                          后台写线程 (1 个)
  ════════════════                        ════════════════

  LOG_INFO ──► append()
                 │ formatLine()               writerThread()
                 │ 加锁 push ────► queue ──►   swap 整批取出
                 │ 立刻返回                   ├─ stdout (可选)
  LOG_WARN ──►  同上                          └─ 文件 (按日滚动)

  LOG_ERROR ─►  同上

  LOG_DEBUG ─►  同上（Release 下编译为空）

  LOG_FATAL ─► fatal()
                 ├─ 也入队 (尽力)
                 ├─ 同步写 stderr (保底)      异步写线程也写一份
                 └─ abort()
```

**核心思想**：业务线程只做「格式化 + 入队」两个轻量操作，不碰磁盘。所有 I/O 交给唯一的后台线程串行处理。

## 二、快速开始

```cpp
#include "wevix_muduo/AsyncLogger.h"

int main() {
    // 1. 初始化（main 第一行）
    wevix_muduo::AsyncLogger::GetInstance().init(
        "./program_log",                    // 日志目录
        wevix_muduo::LogLevel::INFO,        // 最低输出级别
        true                                 // 是否同时输出到终端
    );

    // 2. 随意使用
    LOG_INFO("Server listening on %s:%u", ip, port);
    LOG_WARN("Connection timeout, fd=%d", fd);
    LOG_ERROR("send failed, errno=%d", errno);

    // 3. 退出前（main 最后一行）
    wevix_muduo::AsyncLogger::GetInstance().stop();
    return 0;
}
```

## 三、API 参考

### 3.1 日志级别

```cpp
enum class LogLevel : uint8_t {
    DEBUG = 0,  // 开发调试：数据读写量、帧解析细节
    INFO  = 1,  // 常规运行：连接建立/关闭、服务启停
    WARN  = 2,  // 可恢复异常：超时、重试
    ERROR = 3,  // 操作失败：系统调用错误
    FATAL = 4,  // 致命错误：输出后 abort
};
```

数值越小越详细。`init()` 设置的 `minLevel` 含义：**只输出数值 ≥ minLevel 的日志**。

| minLevel 设为 | 实际输出 | 典型场景 |
|---------------|---------|---------|
| `DEBUG` | DEBUG + INFO + WARN + ERROR + FATAL | 开发调试 |
| `INFO`  | INFO + WARN + ERROR + FATAL | 生产环境 |
| `WARN`  | WARN + ERROR + FATAL | 仅关注异常 |
| `ERROR` | ERROR + FATAL | 仅关注错误 |

### 3.2 日志宏

所有宏都支持 `printf` 风格的格式化字符串。

#### LOG_DEBUG

```cpp
LOG_DEBUG("bytes_read=%zd, buffer_size=%zu", n, inputBuffer_.readableBytes());
```

| 构建类型 | 行为 |
|---------|------|
| Debug（无 `-DNDEBUG`） | 检查 `level() <= DEBUG`，满足则输出 |
| Release（`-DNDEBUG`） | **编译为 `((void)0)`，零指令、零开销** |

#### LOG_INFO

```cpp
LOG_INFO("Server listening on %s:%u", ip, port);
```

始终编译，运行时受 `minLevel` 控制。**所有关键状态变更都应使用 INFO**，确保 Release 下可见。

#### LOG_WARN

```cpp
LOG_WARN("Connection timeout, fd=%d", fd);
LOG_WARN("send on disconnected connection, fd=%d", fd);
```

用于「不正常但不需要立即处理」的情况。

#### LOG_ERROR

```cpp
LOG_ERROR("send failed, fd=%d, errno=%d", fd(), errno);
```

用于系统调用失败、解析失败等需要关注的错误。

#### LOG_FATAL

```cpp
LOG_FATAL("config file %s not found", path);
```

**特殊流程**：
1. 格式化后先入队列（尽力保存到文件）
2. 同步写 `stderr`（**绕过队列**，保证 abort 前一定输出）
3. 调用 `std::abort()`

不用关心 `stop()`，因为进程直接终止。

#### LOG_ERR (兼容旧宏)

```cpp
#define LOG_ERR(fmt, ...) LOG_ERROR(fmt, ##__VA_ARGS__)
```

mprpc 旧代码的别名，直接转发给 `LOG_ERROR`。新代码直接用 `LOG_ERROR`。

### 3.3 AsyncLogger 公共方法

#### GetInstance()

```cpp
static AsyncLogger& GetInstance();
```

Meyers 单例，线程安全。不必手动创建，所有宏内部都通过它获取实例。

---

#### init(logDir, minLevel, consoleOutput)

```cpp
void init(const std::string& logDir = "./program_log",
          LogLevel minLevel = LogLevel::INFO,
          bool consoleOutput = true);
```

**只能调用一次**（在 `main()` 开头）。做的事：

1. 递归创建 `logDir` 目录（类似 `mkdir -p`）
2. 保存 `minLevel` 和 `consoleOutput`
3. 启动后台写线程

**参数说明**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `logDir` | `"./program_log"` | 日志文件存放目录，相对于进程工作目录 |
| `minLevel` | `LogLevel::INFO` | 最低输出级别，低于此级别的日志被过滤 |
| `consoleOutput` | `true` | `true` = 同时写终端 + 文件；`false` = 仅写文件 |

**推荐配置**：

```cpp
#ifndef NDEBUG
    // Debug 构建：DEBUG 级别 + 终端输出，开发时直接看
    AsyncLogger::GetInstance().init("./program_log", LogLevel::DEBUG, true);
#else
    // Release 构建：INFO 级别 + 仅文件，daemon 模式下终端不可见
    AsyncLogger::GetInstance().init("./program_log", LogLevel::INFO, false);
#endif
```

---

#### stop()

```cpp
void stop();
```

**必须在 `main()` 返回前调用**。做的事：

1. 设置 `running_ = false`
2. 调用 `flush()` —— 忙等待队列清空
3. `notify_all` 唤醒写线程
4. `join` 等待写线程退出
5. `fflush` + `fclose` 关闭日志文件

**不调用 stop() 的后果**：队列中未刷出的日志会丢失，后台写线程被强行终止。

---

#### flush()

```cpp
void flush();
```

忙等待直到队列为空，然后 `fflush` 日志文件。一般不需要手动调用，`stop()` 内部会调用。

使用场景：你想在不停止日志系统的情况下强制刷盘（比如 `fork()` 之前）。

---

#### level()

```cpp
LogLevel level() const;
```

返回当前的 `minLevel`（原子读取）。宏内部用它做前置过滤：

```cpp
if (_logger.level() <= LogLevel::DEBUG) { /* 实际格式化+入队 */ }
```

如果当前 `minLevel` 是 `INFO`（值为 1），而宏是 `LOG_DEBUG`（值为 0），则 `1 <= 0` 为 false，直接跳过。

## 四、日志格式解读

### 4.1 输出样本

```
[2026-07-25 15:30:12.826][T12345][INFO ][TcpServer.cpp:42] start() - TcpServer listening on 0.0.0.0:8888
```

### 4.2 字段拆解

```
[2026-07-25 15:30:12.826] [T12345] [INFO ] [TcpServer.cpp:42] start() - TcpServer listening on ...
 ───────────┬───────────  ───┬───  ───┬───  ────────┬────────  ───┬───  ──────────┬──────────
      ① 毫秒时间戳         ② 线程ID   ③ 级别    ④ 文件名:行号   ⑤ 函数名     ⑥ 消息体
```

| # | 字段 | 含义 | 示例 |
|---|------|------|------|
| ① | 时间戳 | `YYYY-MM-DD HH:MM:SS.ms`，毫秒精度 | `2026-07-25 15:30:12.826` |
| ② | 线程ID | `gettid()` 内核线程ID（非 pthread_self） | `T12345` |
| ③ | 级别 | 5 字符右对齐补空格 | `INFO ` / `WARN ` / `ERROR` |
| ④ | 位置 | 文件名（去路径前缀）+ 行号 | `TcpServer.cpp:42` |
| ⑤ | 函数 | 所在函数名（`__func__`） | `start()` |
| ⑥ | 消息 | 用户自定义格式化内容 | `TcpServer listening on ...` |

### 4.3 常用 grep 模式

```bash
# 只看 ERROR 和 FATAL
grep -E '\[ERROR\]|\[FATAL\]' program_log/2026-07-25-log.txt

# 只看某个文件的日志
grep '\[TcpServer.cpp' program_log/2026-07-25-log.txt

# 只看某个线程
grep '\[T12345\]' program_log/2026-07-25-log.txt

# 只看某个时间段
grep '\[2026-07-25 15:3[0-5]' program_log/2026-07-25-log.txt

# 统计各级别日志数量
grep -cE '\[DEBUG\]' program_log/2026-07-25-log.txt
grep -cE '\[INFO \]' program_log/2026-07-25-log.txt
grep -cE '\[WARN \]' program_log/2026-07-25-log.txt
grep -cE '\[ERROR\]' program_log/2026-07-25-log.txt
```

## 五、文件管理

### 5.1 文件位置

```
{logDir}/YYYY-MM-DD-log.txt

例：
./program_log/2026-07-25-log.txt
./program_log/2026-07-26-log.txt
```

### 5.2 日滚动机制

- 文件保持打开状态（`fopen("a+")`），不频繁 open/close
- 每次写日志前检查 `currentDay_`：
  - 同一天 → 沿用已打开的 `FILE*`
  - 跨天了 → 关闭旧文件，打开新的 `YYYY-MM-DD-log.txt`
- 是以「第一条日志写入的时刻」来决定文件名的，不是以日志产生的时刻

### 5.3 目录创建

`init()` 时会递归创建 `logDir`（类似 `mkdir -p`），不存在的父目录也会自动创建。

## 六、Debug vs Release 行为对照

```
                    Debug 构建            Release 构建 (-DNDEBUG)
                    ──────────            ──────────────────────
LOG_DEBUG           输出（如 minLevel=DEBUG）  编译为空，零开销
LOG_INFO            输出                    输出（如 minLevel=INFO）
LOG_WARN            输出                    输出
LOG_ERROR           输出                    输出
LOG_FATAL           输出 + abort            输出 + abort
```

**推荐 init 模式**：

```cpp
#ifndef NDEBUG
    AsyncLogger::GetInstance().init("./program_log", LogLevel::DEBUG, true);
#else
    AsyncLogger::GetInstance().init("./program_log", LogLevel::INFO, false);
#endif
```

### 如何确认当前是什么构建？

```bash
# 查看编译选项中有没有 -DNDEBUG
grep NDEBUG build/CMakeCache.txt
# 或者
grep NDEBUG build/compile_commands.json
```

## 七、内部实现要点

### 7.1 生产者端：轻量附录

业务线程调用 `append()`（由宏触发），做三件事：

```cpp
void AsyncLogger::append(...) {
    // ① 级别过滤 — 原子 load，O(1)
    if (level < minLevel_) return;

    // ② 格式化 — 栈上操作，时间戳有缓存
    std::string lineText = formatLine(...);

    // ③ 加锁入队 + notify — push 后立刻返回
    { lock_guard lock(mutex_); buffer_.push(lineText); }
    cv_.notify_one();
}
```

**关键优化——时间戳缓存**：

```cpp
// 两条连续日志在同一秒内产生：
//   无缓存：2×localtime_r  + 2×chrono::now  + 2×gettid
//   有缓存：2×chrono::now(毫秒部分) + 2×gettid，localtime_r 只调一次
```

`localtime_r` 需要查时区文件，是格式化中最重的操作。缓存将其降为每秒一次。

### 7.2 消费者端：批量处理

后台写线程只有一个，核心循环：

```cpp
void AsyncLogger::writerThread() {
    while (running_) {
        // 等待队列有数据或收到停止信号
        cv_.wait(lock, []{ return !buffer_.empty() || !running_; });

        // swap 整批取出 — 持锁时间 < 1μs
        localQueue.swap(buffer_);

        // 不加锁批量写入
        while (!localQueue.empty()) {
            fprintf(stdout, ...);   // 控制台
            fprintf(logFile, ...);  // 文件
            localQueue.pop();
        }
        fflush(stdout);
        fflush(logFile);            // 一批一刷
    }
}
```

**swap 技巧**：用 `localQueue.swap(buffer_)` 而不是逐条 pop，让锁持有时间极短。然后在锁之外慢慢写盘。

### 7.3 FATAL 的双路径保底

```cpp
void AsyncLogger::fatal(...) {
    // 路径 1：走队列（尽力而为，但 abort 可能来不及）
    { lock_guard lock(mutex_); buffer_.push(line); }
    cv_.notify_one();

    // 路径 2：同步写 stderr（保底，abort 前一定能输出）
    fprintf(stderr, "%s\n", line);
    fflush(stderr);
}
```

### 7.4 DEBUG 的编译期裁剪

```cpp
#ifndef NDEBUG
#define LOG_DEBUG(fmt, ...)  /* 正常执行 */
#else
#define LOG_DEBUG(fmt, ...)  ((void)0)  // 一条指令都不生成
#endif
```

`((void)0)` 是一个合法的空语句，编译器在 `-DNDEBUG` 下直接消除，连参数求值的开销都没有。

## 八、常见问题排查

### Q1：Release 下看不到 LOG_DEBUG？

**答**：设计如此。`LOG_DEBUG` 在 `-DNDEBUG` 下编译期裁剪，不是运行时过滤。如果你在 Release 构建中需要调试级别的日志，改用 `LOG_INFO` 或不要传 `-DNDEBUG`。

### Q2：程序崩溃了但日志文件里没有最后几条日志？

**答**：日志是异步的——业务线程入队后就返回了，后台写线程还没来得及写盘进程就崩了。有以下措施：

- `LOG_FATAL` 会同步写 `stderr`，即使队列来不及刷也能看到
- 正常退出调用 `stop()` 会等队列清空
- 对于 `SIGSEGV` 等非预期崩溃，队列中的日志确实会丢失，这是异步日志的固有取舍

### Q3：日志文件越来越大怎么办？

**答**：当前版本按天滚动但不做定期清理。需要手动或 cron 定期清理旧文件：

```bash
# 删除 30 天前的日志
find ./program_log -name "*.txt" -mtime +30 -delete
```

### Q4：init 没调用就写日志会怎样？

**答**：宏会调用 `GetInstance()`（单例会创建），但 `running_` 为 false，队列没有消费者。日志会堆积在队列中，内存持续增长。务必在 `main()` 第一行调用 `init()`。

### Q5：stop 没调用会怎样？

**答**：队列中未刷出的日志丢失，后台写线程被 `std::terminate` 强制终止。如果 main 正常 return 但没调 `stop()`，析构函数会调 `stop()` 兜底，但析构顺序不确定，不可依赖。

### Q6：多进程写同一个日志文件？

**答**：不支持。每个进程会各自打开文件，`fprintf` 不是原子写，日志会交错。每个进程应该用不同的 `logDir`。
