# 日志系统设计文档

## 一、概述

本项目统一使用 `wevix_muduo::AsyncLogger` 作为日志系统，位于核心库 `wevix_muduo` 中。所有代码（网络库、RPC 框架、业务层）共用同一套日志。

源码位置：
- 头文件：`wevix_muduo/include/wevix_muduo/AsyncLogger.h`
- 实现：`wevix_muduo/src/AsyncLogger.cpp`

---

## 二、设计目标 & 解决的问题

### 改造前的问题
改造前全项目有三种互不统一的日志方式：

| 方式 | 位置 | 问题 |
|------|------|------|
| `::printf` / `::fprintf(stderr)` | wevix_muduo 网络库 | 无时间戳、无级别、无上下文 |
| `std::cout` | mprpc + example | 格式随意，不统一 |
| mprpc `Logger` 类 | mprpc/include/logger.h | 只有 INFO/ERROR 两级，无文件行号/线程ID，每次写日志都 open/close 文件 |

### 改造后的统一方案

```
业务线程                                后台写线程
  │                                         │
  ├─ LOG_INFO ──► append() ──► queue ──► writerThread()
  ├─ LOG_WARN ──► append() ──► queue ──►   ├─ 控制台 stdout
  ├─ LOG_ERROR ─► append() ──► queue ──►   └─ 日志文件 (按日轮转)
  │                                         │
  └─ LOG_FATAL ─► fatal() ──► stderr (同步，绕过队列，abort 前一定刷出)
```

## 三、日志格式

```
[2026-07-23 19:42:29.255][T807407][INFO ][echo_server.cpp:30] main() - Echo Server listening on 0.0.0.0:8888
  │                      │        │       │                    │        └─ 消息内容
  │                      │        │       │                    └─ 函数名
  │                      │        │       └─ 文件名:行号
  │                      │        └─ 日志级别 (DEBUG/INFO/WARN/ERROR/FATAL)
  │                      └─ 线程 ID (gettid)
  └─ 毫秒精度时间戳
```

## 四、五个日志级别

| 级别 | 宏 | 用途 | Release 行为 |
|------|-----|------|-------------|
| DEBUG | `LOG_DEBUG(...)` | 开发调试：数据读写量、帧解析细节 | 编译为空操作，零开销 |
| INFO | `LOG_INFO(...)` | 常规运行：连接建立/关闭、服务启停 | 运行时按级别过滤 |
| WARN | `LOG_WARN(...)` | 非预期但可恢复：连接异常、超时 | 运行时按级别过滤 |
| ERROR | `LOG_ERROR(...)` | 操作失败：系统调用错误、解析失败 | 始终输出 |
| FATAL | `LOG_FATAL(...)` | 致命错误，必须终止进程 | 同步写 stderr 后 abort |

### 使用示例

```cpp
#include "wevix_muduo/AsyncLogger.h"

// 启动时初始化（main 函数第一行）
wevix_muduo::AsyncLogger::GetInstance().init(
    "./program_log",                    // 日志目录
    wevix_muduo::LogLevel::DEBUG,       // Debug 模式输出所有级别
    true                                 // 同时输出到控制台
);

// 业务代码中使用
LOG_INFO("Server listening on %s:%u", ip, port);
LOG_WARN("Connection timeout, fd=%d", fd);
LOG_ERROR("send failed, errno=%d", errno);
LOG_FATAL("config file %s not found", path);  // 输出后 abort

// 退出前
wevix_muduo::AsyncLogger::GetInstance().stop();
```

### 2026-07-23 更新：全面补充日志

本次更新对项目中所有静默忽略错误和缺失状态变更的位置进行了系统性的日志补充。

**一、错误被静默忽略 → 添加 LOG_ERROR（9 处）**

- `Socket.cpp`: `setTcpNoDelay` / `setReuseAddr` / `setReusePort` / `setKeepAlive` 调用 `setsockopt` 失败后原来直接 return，现加 ERROR 日志
- `EventLoop.cpp`: `timerfd_create` / `timerfd_settime` 失败、`eventfd` 创建失败 原来静默忽略
- `EventLoop.cpp`: `wakeup()/handleWakeup()` 中 eventfd 读写失败加 WARN
- `mprpcchannel.cc`: `CallMethod` 中 socket/connect/send/recv/parse 每条失败路径原来只设 controller 错误不打日志，现全部加 ERROR
- `PageCache.cpp`: `systemAlloc` 中 `mmap` 返回 `MAP_FAILED` 加 ERROR
- `PageCache.cpp`: `allocateSpan` 中 `systemAlloc` 返回空加 ERROR
- `CentralCache.cpp`: `fetchRange` 中 `fetchFromPageCache` 返回空加 ERROR
- `ThreadCache.cpp`: `fetchFromCentralCache` 返回空加 ERROR

**二、关键状态变更 → 添加 LOG_INFO / LOG_WARN（9 处）**

- `ThreadPool.cpp`: `start()` / `stop()` 加 INFO，`threadFunc` 线程启动加 DEBUG，线程退出升级为 INFO
- `Connection.cpp`: 构造函数/析构函数加 DEBUG(连接创建/销毁)、`send()` 中 `disconnected_` 为 true 加 WARN
- `Buffer.cpp`: `makeSpace` 扩容时加 WARN
- `mprpcapplication.cc`: `Init` 成功后加 INFO
- `mprpcconfig.cc`: 无效配置行加 WARN、缺失 key 加 WARN
- `rpcprovider.cc`: `NotifyService` 注册服务时加 INFO
- `TcpServer.cpp`: `enableWorkPool` 重复调用加 WARN
- `Channel.cpp`: `handleEvent` 中 EPOLLHUP 加 DEBUG

**三、日志级别调整 → 解决 Release 不可见（4 处）**

- `Connection.cpp` `handleClose`: `LOG_DEBUG` → `LOG_INFO`
- `Acceptor.cpp` `handleRead`: `LOG_DEBUG` → `LOG_INFO`
- `EventLoop.cpp` `handleTimer`: `LOG_DEBUG` → `LOG_INFO`

**四、示例程序 → NDEBUG 控制终端输出 + 补充 stop()**

所有 5 个示例程序改为按构建类型自动切换：

```cpp
#ifndef NDEBUG
    AsyncLogger::GetInstance().init("./program_log", LogLevel::DEBUG, true);   // Debug: 终端+文件
#else
    AsyncLogger::GetInstance().init("./program_log", LogLevel::INFO, false);   // Release: 仅文件
#endif
```

补充 `stop()` 调用：`userservice.cc`、`calluserservice.cc`、`callfriendservice.cc` 原来退出前未调用 stop()，可能导致缓冲日志丢失。

## 六、异步实现：如何解决磁盘 I/O 性能开销

### 问题

磁盘写入是日志系统最大的性能瓶颈。如果每条日志都同步写盘，高频路径（如网络 I/O）会产生严重的延迟抖动。

### 方案：生产者-消费者异步模型

```
    [业务线程 1] ──┐
    [业务线程 2] ──┤  formatLine()    ┌──────────┐
    [业务线程 3] ──┼──► 加锁入队 ──► │  LockQueue │
    [业务线程 N] ──┘    立刻返回      └─────┬────┘
                                            │
                                    ┌───────▼────────┐
                                    │  后台写线程 ×1   │
                                    │  swap 整批取出    │
                                    │  stdout + file   │
                                    └─────────────────┘
```

### 具体优化点

**1. 生产者端（业务线程）—— 只做轻量操作**

```cpp
void AsyncLogger::append(...) {
    // ① 级别过滤：一条原子 load，不满足直接返回
    if (level < minLevel_) return;

    // ② 格式化：栈上操作，无堆分配。时间戳有缓存，同秒内不调 localtime_r
    std::string line = formatLine(...);

    // ③ 入队 + notify：只加锁 push，O(1)，立即返回
    { lock_guard lock(mutex_); buffer_.push(line); }
    cv_.notify_one();
}
```

业务线程不做任何磁盘 I/O。

**2. 时间戳缓存 —— 减少系统调用**

```cpp
// 2 条连续日志同一秒内产生：
// 无缓存：2×localtime_r + 2×chrono::now + 2×gettid
// 有缓存：2×chrono::now(毫秒) + 2×gettid，localtime_r 复用
```

`localtime_r` 需要查时区文件，是日志格式化中最重的操作。缓存将其降为每秒一次。

**3. 消费者端（后台线程）—— 批量交换 + 批量刷盘**

```cpp
void writerThread() {
    while (running_) {
        // swap 整批取出，持锁时间极短
        localQueue.swap(buffer_);  // ＜ 1μs

        // 不加锁批量写入
        for (auto& item : localQueue) {
            fprintf(file, "%s\n", item.text);
        }
        fflush(file);  // 批量刷一次
    }
}
```

每条日志一条 `fprintf` + 一批一条 `fflush`。如果要更高吞吐，可以去掉 `fflush` 让 OS 缓冲管理。

**4. LOG_DEBUG 编译期裁剪 —— Release 零开销**

```cpp
#ifndef NDEBUG
#define LOG_DEBUG(fmt, ...) /* 正常执行 */
#else
#define LOG_DEBUG(fmt, ...) ((void)0)  // 编译为空，一条指令都不生成
#endif
```

**5. LOG_FATAL 特殊处理 —— 绕过队列同步输出**

```cpp
void fatal(...) {
    // 也入队（尽力保存到文件）
    { lock_guard lock(mutex_); buffer_.push(line); }
    cv_.notify_one();

    // 直接同步写 stderr（保底，abort 前一定输出）
    fprintf(stderr, "%s\n", line);
    fflush(stderr);
}
```

## 七、文件管理

- 日志文件存放在 `logDir` 目录（默认 `./program_log/`）
- `init()` 时自动创建目录（`mkdir -p`）
- 文件名格式：`YYYY-MM-DD-log.txt`
- 文件保持打开状态，跨天自动关闭旧文件、打开新文件
- 不再像旧 Logger 那样每条日志打开/关闭一次文件

## 八、初始化

```cpp
#include "wevix_muduo/AsyncLogger.h"

int main() {
    // 推荐：按构建类型自动切换
#ifndef NDEBUG
    // Debug 模式：DEBUG 级别 + 终端输出，便于开发调试
    wevix_muduo::AsyncLogger::GetInstance().init(
        "./program_log", wevix_muduo::LogLevel::DEBUG, true);
#else
    // Release 模式：INFO 级别 + 仅写文件，终端不输出日志
    wevix_muduo::AsyncLogger::GetInstance().init(
        "./program_log", wevix_muduo::LogLevel::INFO, false);
#endif

    // ... 业务代码 ...

    // 最后一行调用，等队列清空 + 刷盘
    wevix_muduo::AsyncLogger::GetInstance().stop();
    return 0;
}
```

建议：
- **开发/调试**：`LogLevel::DEBUG, consoleOutput=true`，可以看到完整 I/O 细节和连接生命周期
- **生产环境**：`LogLevel::INFO, consoleOutput=false`，日志仅写入文件，终端不输出，避免 I/O 拖慢和 daemon 模式下 stdout 丢失。Release 构建时 `LOG_DEBUG` 编译期裁剪、零开销
- **纯 CLI 工具**：可以始终开启 consoleOutput，方便用户在终端直接看到结果
