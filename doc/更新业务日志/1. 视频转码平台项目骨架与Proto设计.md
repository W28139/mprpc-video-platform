## 1. Proto 协议设计

### 1.1 共享类型 (`common.proto`)

三种状态枚举（proto3 枚举值在同一 package 内必须唯一，全部加了前缀）：

- `JobStatus`：JOB_PENDING → JOB_SPLITTING → JOB_SCHEDULING → JOB_RUNNING → JOB_MERGING → JOB_SUCCESS / JOB_FAILED / JOB_CANCELED
- `ShardStatus`：SHARD_CREATED → SHARD_WAITING → SHARD_ASSIGNED → SHARD_RUNNING → SHARD_SUCCESS / SHARD_FAILED / SHARD_RETRYING / SHARD_CANCELED
- `WorkerStatus`：WORKER_ONLINE / WORKER_OFFLINE / WORKER_DRAINING

三个实体消息：`JobInfo`（12 字段）、`ShardInfo`（14 字段）、`WorkerInfo`（10 字段）。外加 `WorkerLoad` 用于心跳上报。

### 1.2 五个 service 定义

| Proto 文件 | Service | RPC 方法 |
|-----------|---------|---------|
| `job.proto` | `JobService` | SubmitJob / QueryJob / CancelJob |
| `scheduler.proto` | `SchedulerService` | ScheduleJob / RescheduleShard |
| `worker.proto` | `WorkerManagerService` | RegisterWorker / Heartbeat / ListWorkers |
| `worker.proto` | `WorkerService` | AssignShard / CancelShard / QueryShard |
| `result.proto` | `ResultCollectorService` | ReportShardProgress / ReportShardResult |

### 1.3 编译方式

使用 `protoc` 生成 C++ 代码到 `proto/generated/`，`.pb.cc/.pb.h` 文件提交进仓库（与现有 `mprpc/src/rpcheader.pb.cc` 和 `test/proto/*.pb.cc` 的方式一致）。

`CMakeLists.txt` 中提供了 `gen_protos` 自定义目标，修改 proto 后可手动运行：

```bash
cmake --build build --target gen_protos
```

## 2. 内存存储层

实现位置：`video_platform/include/video_platform/common_store.h` + `video_platform/src/common_store.cpp`

三个单例 Store，每个内部用 `std::unordered_map` + `std::shared_mutex`（写锁 unique_lock，读锁 shared_lock）：

| Store | Key | 查询接口 |
|-------|-----|---------|
| `JobStore` | job_id | Get / Insert / Update / Delete / ListAll / Count |
| `ShardStore` | shard_id | Get / Insert / Update / Delete / ListByJob / ListByWorker / ListAll |
| `WorkerStore` | worker_id | Get / Insert / Update / Delete / ListByStatus / ListAll |

辅助函数：`GenerateId(prefix)` 生成唯一 ID（格式 `prefix_timestamp_counter_random`），`NowMs()` / `NowSec()` 时间戳工具。

### 设计要点

- `JobStore::Get()` 返回裸指针而非 shared_ptr，因为锁定期间调用方读取完毕后锁才释放。调用方不要持有该指针跨越锁边界
- `ListByJob()` 和 `ListByWorker()` 返回 `vector` 副本，避免返回引用的锁安全问题
- `Insert()` 使用 `try_emplace`，重复插入返回 false（防重复创建）

## 3. 服务骨架

### 3.1 统一模式

每个服务 main() 按以下流程，与现有 `test/mprpc/user_provider.cc` 保持一致：

```cpp
1. AsyncLogger::GetInstance().init()   // Debug: 终端输出, Release: 仅写文件
2. MprpcApplication::Init(argc, argv)  // 解析 -i config.conf
3. RpcProvider provider
4. provider.NotifyService(new XxxServiceImpl())
5. provider.Run()                      // 阻塞: 连接 ZK + 注册服务 + 启动 TcpServer
```

### 3.2 各服务现状

| 服务 | 端口 | 当前行为 |
|------|------|---------|
| `job_service` | 9001 | SubmitJob: 创建 JobRecord 写内存，返回 job_id。QueryJob: 查内存返回。CancelJob: 改状态为 CANCELED |
| `scheduler_service` | 9002 | ScheduleJob / RescheduleShard：只打日志返回 accepted=true |
| `worker_manager` | 9003 | RegisterWorker: 写 WorkerStore。Heartbeat: 更新心跳时间。ListWorkers: 按状态过滤返回 |
| `transcode_worker` | 9004 | AssignShard / CancelShard / QueryShard：只打日志 |
| `result_collector` | 9005 | ReportShardProgress / ReportShardResult：只打日志 |

### 3.3 编译产物

| 目标 | 二进制 | 大小 |
|------|-------|------|
| `job_service` | `bin/job_service` | 7.3MB |
| `scheduler_service` | `bin/scheduler_service` | 6.4MB |
| `worker_manager` | `bin/worker_manager` | 7.4MB |
| `transcode_worker` | `bin/transcode_worker` | 6.6MB |
| `result_collector` | `bin/result_collector` | 6.4MB |
| `video_common` | `lib/libvideo_common.a` | 静态库 |

## 4. CMAKE 构建集成

`video_platform/CMakeLists.txt` 编译 proto 生成的 `.pb.cc` 为静态库 `video_common`，五个服务链接该库。

根 `CMakeLists.txt` 新增一行：

```cmake
add_subdirectory(video_platform)
```

项目现有 build 不受影响——`test/` 中的老压测和示例仍然能正常编译运行。

## 5. 测试验证

```bash
# 编译
cmake -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j$(nproc)

# 启动 ZooKeeper，然后依次启动服务
./bin/job_service -i video_platform/conf/job_service.conf &
./bin/scheduler_service -i video_platform/conf/scheduler.conf &
./bin/worker_manager -i video_platform/conf/worker_manager.conf &
./bin/transcode_worker -i video_platform/conf/transcode_worker.conf &
./bin/result_collector -i video_platform/conf/result_collector.conf &

# 用 ZK CLI 验证注册
./bin/zkCli.sh -server 127.0.0.1:2181 ls /mprpc/services
# 输出: [JobService, SchedulerService, WorkerManagerService, WorkerService, ResultCollectorService]
```
